# onetime-ruby Modernization Plan

> Status: Draft for review · Date: 2026-06-19 · Target: `1.0.0`
>
> Update: the first release under this plan shipped as `onetime` **0.6.0**. The
> canonical package becomes `onetimesecret` in **0.7.0**, with `onetime` retained
> only as a compatibility package. The version stays below 1.0 until the API
> surface has settled; references to "1.0" below describe this body of work.

This document is the implementation plan for bringing the official Ruby client
from its current 2013-era state (`v0.5.1`) up to a modern, Ruby 3 client library
that supports the OnetimeSecret **v2** and **v3** APIs, follows current Ruby
library best practices, and meets the developer-experience (DX) bar expected of
an *official* client.

It is deliberately a plan, not a code change. Implementation proceeds in the
phases described in [§7](#7-phased-roadmap).

---

## 1. Decisions (locked)

These were agreed before drafting and constrain everything below:

| Decision | Choice | Rationale |
|---|---|---|
| **Ruby floor** | **3.1+** | Broadest reach across the many environments a client runs in; CI-tested through 3.4/head. A client cannot demand 3.4 the way the server does. |
| **HTTP stack** | **Zero-dependency `Net::HTTP`** | No runtime gems → no transitive-dependency conflicts in host applications. An optional adapter seam lets advanced users plug in Faraday. This is the single biggest "runs everywhere" win. |
| **CLI** | **Separate `onetime-cli` gem** | Keeps the library gem dependency-free. CLI deps (Thor, etc.) never leak into apps that only want the library. |
| **Default API version** | **v3**, with **v2** opt-in and a thin **v1** compatibility shim | Matches the server's current direction; gives `0.5.x` users a migration path. |

---

## 2. Current State (the diagnosis)

The library is a single ~140-line file plus a CLI, last released **2013-02-12**.

**Structure**
- `lib/onetime/api.rb` — the entire library.
- `bin/onetime` — CLI built on `drydock`.
- `onetime.gemspec` — generated by `jeweler`.

**Problems**
- **Dead / heavy dependencies**: `httparty` (heavy), `drydock` (abandoned CLI
  DSL), `jeweler` (abandoned gem tooling), `yajl-ruby` fallback. `json` is now
  stdlib.
- **API v1 only**: `base_uri` is hardcoded; `api_path` forces `v#{apiversion}`
  defaulting to `1`. Endpoints are the legacy `/share`, `/generate`,
  `/secret/:key`, `/metadata/:key`, `/status`.
- **Stale auth model**: HTTP Basic with `custid` (email) + `key`. The server
  now authenticates the **customer extid** (the `ur...` identifier shown at the
  bottom of the user menu) in the username slot + an **API token** as the
  password.
- **No engineering hygiene**: no tests, no CI, no RuboCop, no type signatures,
  no SemVer discipline. Gem signing points at a non-existent
  `/mnt/gem/gem-private_key.pem`.
- **Fragile code**: `File.read(path).strip!` can return `nil`; a hand-rolled
  `indifferent_params` hash hack; CLI `stty` shell-outs.

## 3. Target API Surface (what the server actually offers)

Three generations are live (mounted under `/api/v1`, `/api/v2`, `/api/v3`):

| | v1 (frozen) | v2 | v3 |
|---|---|---|---|
| JSON types | strings, `content=form` | **all fields string-serialized** | **native JSON** (numbers/bools/null) |
| Auth | basic + anonymous | `basicauth` + `noauth` (anon allowed) | `sessionauth` + `noauth` guest routes |
| Verbs | mostly POST | GET/POST/PATCH/OPTIONS | GET/POST/PATCH/OPTIONS |
| Vocabulary | `metadata` / `private` | **`receipt`** canonical | `receipt` only (legacy `metadata` removed) |
| Errors | legacy `{ message }` | **ADR-013** `{ error, error_type, … }` | ADR-013 |

**v3 secret operations** (the modern surface; v2 mirrors these with string
values and allows anonymous basic auth):

- `POST /secret/conceal` — store a user-provided secret → secret link + receipt.
- `POST /secret/generate` — server-generated secret value + receipt.
- `POST /secret/:id/reveal` — retrieve & decrypt once.
- `GET  /secret/:id` — show secret metadata without revealing.
- `GET  /secret/:id/status`, `POST /secret/status` — status (no auth).
- `GET  /receipt/recent`, `GET /receipt/:id`, `PATCH /receipt/:id`,
  `POST /receipt/:id/burn` — creator-facing receipt management.
- Meta: `GET /status`, `GET /version`, `GET /supported-locales`,
  `POST /feedback`.
- **Guest routes** under `/guest/*` allow anonymous use of conceal/generate/
  reveal/receipt when enabled server-side.

**Auth asymmetry to model**: v2 accepts API-token HTTP Basic *and* anonymous;
v3 secret routes require **session auth**, with anonymous access only on the
`/guest/*` routes. The client must support both credential modes and route to
`/guest/*` when operating anonymously against v3.

**Error contract (ADR-013)**: 4xx/5xx bodies are
`{ error: <human message>, error_type: <ClassName>, … }`. Class-specific extras
include `field` (FormError), `error_key` (i18n), `retry_after`/`attempts`/
`max_attempts` (LimitExceeded), `entitlement`/`current_plan`/`upgrade_to`
(EntitlementRequired), and `code` (e.g. `GUEST_CONCEAL_DISABLED`).

The server also generates an **OpenAPI spec** (`scripts/openapi/`), with each
logic class declaring `SCHEMAS = { response:, request: }`. This is the source of
truth for request/response shapes and should drive contract tests.

## 4. Design Principles

1. **Zero runtime dependencies by default.** Stdlib `Net::HTTP` + `json`.
2. **Portability over cleverness.** Works on Ruby 3.1–3.4, MRI primarily;
   no monkey-patching, no global state, thread-safe client instances.
3. **Faithful, per-version responses.** Each API version returns its own
   response shape and the client preserves it as-is (wrapped in an
   indifferent-access `Onetime::Response`). v1, v2, and v3 are deliberately
   different wire contracts; the client does NOT normalize them to a common
   shape. (v1 is deprecated and present only because the API still serves it.)
   No type system (RBS/Sorbet).
4. **Errors are exceptions.** Map `error_type` → a class hierarchy; never make
   callers branch on HTTP status strings.
5. **Self-hosting friendly.** `base_url` is first-class; OnetimeSecret is widely
   self-hosted.
6. **Explicit, documented configuration.** Timeouts, retries, user-agent,
   logger, proxy — all settable, all with sane defaults.

## 5. Proposed Public API (sketch)

```ruby
require "onetimesecret"

client = Onetime::Client.new(
  base_url:     "https://ca.onetimesecret.com", # region/self-hosted/custom (required)
  api_version:  :v3,                            # :v3 (default), :v2, :v1 (shim)
  customer:     "ur1abc23def",                  # customer extid (HTTP Basic username)
  api_token:    ENV["ONETIME_API_TOKEN"],       # HTTP Basic token (v2) ...
  # session:    "...",                          # ... or session for v3 authed routes
  timeout:      10,
  max_retries:  2,                              # idempotent requests only
)

# Conceal a secret you already have
receipt = client.secrets.conceal(secret: "hunter2", ttl: 3600, passphrase: "pw")
receipt.secret_url      # => "https://ca.onetimesecret.com/secret/abc..."
receipt.receipt_url
receipt.ttl             # => 3600 (Integer, regardless of v2/v3)

# Generate a secret
client.secrets.generate(ttl: 86_400)

# Reveal (one-time)
secret = client.secrets.reveal("abc...", passphrase: "pw")
secret.value

# Receipts (creator-facing)
client.receipts.recent
client.receipts.show(key)
client.receipts.burn(key)

# Meta (no auth)
client.status      # => "nominal"
client.version

# Anonymous / guest usage against v3 routes /guest/*
guest = Onetime::Client.new(api_version: :v3)  # no creds
guest.secrets.conceal(secret: "...")           # routed to /guest/secret/conceal
```

Errors:

```ruby
begin
  client.secrets.reveal("missing")
rescue Onetime::RecordNotFound => e
  e.message      # human-readable
  e.error_type   # "RecordNotFound"
rescue Onetime::LimitExceeded => e
  e.retry_after
end
```

### Internal layout

```
lib/
  onetime.rb                      # entrypoint, requires + version
  onetime/
    version.rb
    client.rb                     # config + resource accessors
    configuration.rb
    transport.rb                  # Net::HTTP core (timeouts, retries, headers)
    adapter.rb                    # optional pluggable HTTP adapter seam
    errors.rb                     # ADR-013 mapping → exception hierarchy
    response.rb                   # indifferent-access wrapper (per-version shape)
    resources/
      secrets.rb
      receipts.rb
      meta.rb
    api/
      v3.rb                       # path/verb maps + native-type handling
      v2.rb                       # path/verb maps + string-typed responses
      v1.rb                       # path/verb maps + legacy form params
```

## 6. Engineering Hygiene

- **Tooling**: `standard` (or RuboCop), `frozen_string_literal: true` everywhere.
- **Tests**: Minitest with dependency-injected fake transports for resource/
  request-building coverage, real `Net::HTTP` integration tests via a local
  one-shot TCP server, and opt-in live tests against the real API (gated by
  `ONETIME_LIVE`). No type system (RBS/Sorbet).
- **Docs in code**: YARD doc comments only.
- **CI**: GitHub Actions matrix Ruby `3.1, 3.2, 3.3, 3.4, head` × lint/test;
  contract-test job that pulls the published OpenAPI spec.
- **Release**: SemVer, real `CHANGELOG.md` (Keep a Changelog), **RubyGems
  Trusted Publishing** (OIDC) — retire the broken cert-signing flow and
  `jeweler` entirely. Gemspec authored by hand.
- **Docs**: rewritten `README.md`, usage examples, and self-hosting
  configuration notes. (No 0.5.x migration guide — see §8, clean break.)

## 7. Phased Roadmap

| Phase | Scope | Exit criteria |
|---|---|---|
| **0. Plan** | This document | Reviewed & approved |
| **1. Foundation** | New gem skeleton; hand-written gemspec; drop jeweler/drydock/httparty/yajl; `version.rb`; CI matrix; Minitest; `CHANGES.txt`; Trusted Publishing | Empty client builds, CI green on 3.1–3.4 |
| **2. Transport core** | `Net::HTTP` transport (base_url, auth modes, timeouts, retries+backoff, headers/UA); ADR-013 error mapping; optional adapter seam | Unit-tested transport + full error hierarchy |
| **3. v3 resources** (default) | secrets (conceal/generate/reveal/show/status), receipts (recent/show/update/burn), meta, feedback; guest-route handling; per-version response shapes | v3 happy-path + error paths covered |
| **4. v2 + v1** | v2 resources (string-typed responses) + anonymous basic auth; v1 resources (legacy form params/endpoints), deprecated but supported while the API serves it | v1 and v2 covered (incl. live tests) |
| **5. CLI gem** | New `onetime-cli` gem on Thor; commands `share`/`generate`/`reveal`/`receipt`/`status`; stdin piping; json/yaml output | CLI installs & runs against live API |
| **6. Docs & 1.0** | README, examples, self-hosting notes; tag `1.0.0` | Published to RubyGems via OIDC |

## 8. Compatibility & Migration

`1.0` is a **clean break** from the 0.5.x release (2013). No backward
compatibility is maintained:

- **No `OT::API` shim**: the legacy `Onetime::API`/`OT::API.new`/`get`/`post`
  surface and the `OT` top-level alias are removed. `Onetime::Client` is the
  only interface.
- **No legacy env vars**: only `ONETIME_BASE_URL`, `ONETIME_CUSTOMER_EXTID`, and
  `ONETIME_API_TOKEN` are read (the old `ONETIME_HOST`/`ONETIME_CUSTID`/
  `ONETIME_APIKEY` are gone).
- **CLI users**: `onetime` moves to a separate `onetime-cli` gem; the dead
  `drydock`-based `bin/onetime` is removed.

## 9. Open Questions / Risks

1. **v3 session auth for non-browser clients** — v3 secret routes require
   `sessionauth`. Need to confirm the supported programmatic path for obtaining/
   presenting a session from a server-to-server client (vs. relying on v2
   API-token basic auth or `/guest/*`). *This determines whether headless v3
   automation is fully supported or steers integrators to v2.*
2. ~~**Gem name**~~ — **resolved: the canonical gem is `onetimesecret`.**
   `onetime` 0.7 is a dependency-only compatibility package. `onetime-ruby`
   remains the repository name for the Ruby SDK.
3. **Idempotency/retries** — confirm which endpoints are safe to auto-retry
   (GETs and status; conceal/generate are not idempotent).
4. **OpenAPI spec distribution** — is the generated spec published at a stable
   URL the client's contract tests can fetch in CI?
